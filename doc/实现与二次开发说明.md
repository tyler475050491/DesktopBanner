## 2. 线程与消息模型

```
Banner_InitEx
   └─ StartBanner()  [g_lifeMutex]
        ├─ 若已在运行 → StopInternal()
        ├─ 写 g_state（参数快照）  [g_stateMutex]
        ├─ CreateEvent(ready) / CreateEvent(done)
        ├─ std::thread(RunBannerThread)
        └─ WaitForSingleObject(ready, 5s)  → 拿到启动结果
```

渲染线程 `RunBannerThread`：

1. `SetThreadDpiAwarenessContext(PER_MONITOR_AWARE_V2)`（**只影响本线程**，不改宿主的 DPI 感知）；
2. `timeBeginPeriod(1)` 提高定时器精度；
3. 注册窗口类 `DoubaoDesktopBannerWnd`；
4. `CreateWindowExW(WS_POPUP, ...)` → `ShowWindow(SW_SHOWNOACTIVATE)` → `SetWindowPos(TOPMOST/BOTTOM)`；
5. `SyncBanner()`（建缓冲、生成背景、量文字）+ `RenderBanner()` 首帧；
6. 通知 ready，`SetTimer(16ms)`，进入 `GetMessage` 循环；
7. 收到 `WM_DB_QUIT` → `DestroyWindow` → `PostQuitMessage` → 循环退出 → 释放缓冲/字体/DC → 通知 done。

外部改参数统一用 `PostMessage(WM_DB_REFRESH)`（**不用** `SendMessage`，避免宿主线程等渲染线程、渲染线程又等锁的死锁）。

## 3. 渲染管线

关键点：**不用 `SetLayeredWindowAttributes`，用 `UpdateLayeredWindow` 逐像素 alpha**。
前者只能"整窗一个透明度"或"一种颜色做 ColorKey"，做不到"半透明背景 + 不透明清晰文字"同时成立。

每帧（16ms）三步：

1. **文字蒙版**：在 32bpp DIB 上 `FillRect` 黑底，用 `DrawTextW` 画白色文字；
   字体质量固定 `ANTIALIASED_QUALITY`（灰度抗锯齿，不能用 ClearType，否则彩色边缘会污染覆盖率）；
2. **合成**：把预生成的背景层 `memcpy` 到帧缓冲，再按"蒙版亮度 = 文字覆盖率"逐像素混合：

   ```
   cov  = mask 像素亮度 (0~255)
   outA = cov + bgA*(255-cov)/255
   outR = (textR*cov + bgR*(255-cov))/255      // bgR 已是预乘 alpha 的值
   ```

   全部按 **premultiplied BGRA** 计算，`A` 通道和 `RGB` 同时保持预乘关系，否则边缘会出现"白边/黑边"；
3. **提交**：`UpdateLayeredWindow(hwnd, screenDC, NULL, &size, frameDC, &srcPt, 0, &blend, ULW_ALPHA)`。
   传 `NULL` 的 `ptDst` 表示"位置不变只更新内容"，移动窗口交给 `SetWindowPos`。

## 4. 磨砂是怎么做出来的

`BuildBackground()` 一次性生成整条背景（样式变化时才重算），每帧只做 `memcpy`，开销可以忽略：

- 基色 = `bgColor`；
- 垂直渐变：顶部 +8、底部 −8 灰度，做出玻璃厚度感；
- 上下 1px：顶边 +22 高光、底边 −18 阴影，模拟玻璃边缘；
- 颗粒：`Hash2D(x, y)` 生成的**确定性噪声**（±(frost/100×12)），
  因为基于坐标而不是随机数，所以**每帧完全一致、不会闪**；`frost = 0` 时以上三项全关，退化为纯色平涂。

> 这不是真正的背景模糊。DWM 的 `ACCENT_ENABLE_BLURBEHIND / acrylic` 只对非分层窗口生效，
> 与逐像素 alpha 的分层窗口互斥，所以这里用"半透明 + 颗粒 + 渐变"来近似"磨砂玻璃"观感。

## 5. 滚动算法

```
cycle = 文字宽度 + 间隔(GapOf)
advance += speed(px/s) × dt(秒)          // dt 来自 QueryPerformanceCounter，与定时器精度无关
advance = fmod(advance, cycle)           // 保持在一个周期内，避免长跑后精度漂移
绘制位置 x = 横幅宽度 − advance
为了无缝：按 x + k×cycle (k = −n..n) 重复绘制文字，覆盖整条横幅
```

- 正速度 → `advance` 增大 → `x` 减小 → 文字向左；负速度反向。
- 因为按周期重复绘制，位置取模不会造成"跳"，两个方向都成立。
- `dt` 上限截到 0.2s：系统休眠/卡顿回来时不会一下跳出去很远。
- 文字变更时 `advance` 归零，从最右侧重新滚入，视觉上更自然。

## 6. 鼠标穿透（三件套，缺一不可）

1. `WS_EX_TRANSPARENT`：分层窗口配合它，命中测试整体跳过（这是主手段）；
2. `WM_NCHITTEST → HTTRANSPARENT`：即使将来去掉 ex 样式，鼠标也会落到下层；
3. `WS_EX_NOACTIVATE` + `WM_MOUSEACTIVATE → MA_NOACTIVATE`：永不抢焦点，点它不会把宿主窗口激活。

另外 `WS_EX_TOOLWINDOW` 让它不出现在任务栏和 Alt+Tab；`WS_POPUP` 无边框，不会画标题栏。

实测：`WindowFromPoint(500,20)` 在横幅区域内命中的是下层窗口，而不是横幅本身。

## 7. 构建参数为什么这么定

```bat
cl /LD /MT /O2 /W4 /utf-8 /Zi ...
```

| 参数 | 原因 |
|---|---|
| `/MT` | 静态链 CRT → DLL/EXE 只依赖系统 DLL，**不需要 VC++ 运行库**，拷走就能跑 |
| `/utf-8` | 源码是 UTF-8（带 BOM）+ 中文注释，避免 MSVC 按 GBK 误读 |
| `/LD` + `.def` | 明确导出名为 `Banner_Init` 这种干净名字，方便 `GetProcAddress` |
| `/O2` | 每帧要合成 1920×52 像素，优化有必要 |
| `/W4` | 保持零警告（当前编译输出没有任何 warning） |

- 换 **x86**：把 `build.bat` 里的 `vcvars64.bat` 改成 `vcvars32.bat`，并把 `.def` 里每个导出改成
  `Banner_Init = _Banner_Init@16` 这种带修饰的形式（x86 `__stdcall` 会加修饰）；
  不想改 def 就动态 `GetProcAddress` 时用修饰名，或干脆把 `DB_CALL` 改成空（x86 用 cdecl）。
- 换 VS 版本：`build.bat` 用 `vswhere` 自动定位，2017/2019/2022 都能用。

## 8. 调试与自测

### 示例程序的诊断日志

`BannerDemo.exe` 在控件创建失败时会写 `%TEMP%\banner_demo_dbg.log`（UTF-8）。
正常情况不产生该文件。

### 已验证项（本机 Windows 10 · 1920×1080 · 100% 缩放）

| 验证项 | 方法 | 结果 |
|---|---|---|
| 导出完整性 | `dumpbin /exports DesktopBanner.dll` | 15 个 `Banner_*` 全部导出 |
| 窗口样式 | `GetWindowLongPtr(GWL_EXSTYLE)` | `0x080800A8` → LAYERED / TRANSPARENT / TOOLWINDOW / NOACTIVATE / TOPMOST 全在 |
| 窗口位置 | `GetWindowRect` | `(0,0)-(1920,52)`，与 `height=52` 一致 |
| 鼠标穿透 | `WindowFromPoint` 在横幅区域内取点 | 命中下层窗口（Chrome / CabinetWClass），非横幅 |
| 滚动 | 间隔 700ms 两次抓屏做像素差分 | 1200+ 采样点变化，确认在动 |
| 磨砂/透明度 | 抓屏放大观察 | 半透背景可见下层内容，带渐变与颗粒，文字边缘平滑 |
| 接口 1 | 点"初始化/重建" | 新建窗口、日志 `Banner_InitEx() = TRUE (16 ms)` |
| 接口 2 | 点"应用样式"/拖滑块 | 窗口句柄不变，颜色/alpha/速度实时变化 |
| 接口 3 | 点"设置文字" | `Banner_SetTextW/SetTextA = TRUE`，文字变更并复位滚动 |
| 接口 4 | 点"关闭横幅" | 句柄消失、`Banner_IsActive() = FALSE`；再初始化可恢复 |

### 常见坑（真踩过的）

1. **`CreateWindowEx` 建子控件返回 NULL、`GetLastError()` = 1401 (`ERROR_CANNOT_FIND_WND_CLASS`)**
   —— 不是类名写错，而是**样式里漏了 `WS_CHILD`**：给一个带父窗口的 RichEdit/EDIT 传了不带 `WS_CHILD` 的样式，
   窗口会被当顶层窗口创建，class 查找走另一条路径直接失败。修法：样式里加 `WS_CHILD | WS_VISIBLE`。
2. **`ConvertFrom-Json` / `rc` 编码**：`.rc` 里有中文，编译要带 `/c 65001`；源码文件建议 UTF-8 **带 BOM**，否则 VS 打开是乱码。
3. **不要用 `SendMessage` 改参数**：宿主线程会阻塞在渲染线程上，极端情况死锁。
4. **每帧别重建字体/背景**：字体和背景层都做了"参数变了才重建"的判断，改代码时别把这个判断去掉，
   否则 60fps 下会持续 `CreateFont`/分配内存。

## 9. 已知限制与扩展点

| 限制 | 现状 | 怎么扩展 |
|---|---|---|
| 真·背景模糊 | 用颗粒+渐变模拟 | 改成非分层窗口：`WS_EX_NOREDIRECTIONBITMAP` 不需要，但要用 `SetWindowCompositionAttribute(ACCENT_ENABLE_BLURBEHIND)` + 子窗口画文字；代价是失去逐像素 alpha 文字控制 |
| 仅主显示器 | `ComputeGeometry()` 用 `GetSystemMetrics(SM_CXSCREEN)` | 换成 `MonitorFromWindow/GetMonitorInfo`，并把窗口矩形算到目标显示器 |
| 单行文字 | `DrawTextW(..., DT_SINGLELINE)` | 需要多行就按行高分配高度、逐行画到蒙版 |
| 无圆角 | 矩形窗口 | 在合成阶段把四角像素的 `cov` 乘一个圆角遮罩即可（不用改窗口样式） |
| 不可交互 | 全程穿透 | 要去掉 `WS_EX_TRANSPARENT`，并给 `WM_NCHITTEST` 返回 `HTCLIENT`；再自己处理 `WM_LBUTTONDOWN`（注意别抢焦点） |
| 无托盘/配置持久化 | 由宿主负责 | 建议在宿主里存 JSON/INI，启动时读出来喂 `BannerOptions` |

## 10. 想加一个接口？按这个顺序改

1. `DesktopBanner.h` 加声明 + 注释 + 错误码（如需）；
2. `DesktopBanner.cpp` 实现（改参数 → `PostRefresh()`；要重建窗口 → `StartBanner()`）；
3. `DesktopBanner.def` 加一行导出；
4. `BannerDemo.cpp` 的 `BannerApi` 结构体加字段 + `LOADAPI(...)` 一行；
5. `build.bat` 跑一次，`dumpbin /exports` 确认导出，再跑 Demo 验证。
